# 트레이딩 데이터 기록과 연구 설계

## 현재 범위

모의 실행기의 JSONL 원본은 유지하고 SQLite는 조회용 복사본으로 사용한다. 실행기 이벤트에는 판단·시각·뉴스·비용과 주문 상태가 기록된다. 새 실행부터 판단에 사용한 NH KRX 완료 1분봉을 함께 남긴다. 과거 기록에 없는 가격·입력·모델 버전·수수료는 추정하여 채우지 않는다. 모의와 실계좌 기록은 혼합하지 않으며 이 저장소는 실주문 권한을 주지 않는다.

## 데이터 흐름

시세·뉴스(발생/조회 시각, 출처) → 당시 입력과 모델 판단(모델 버전, 질문, 사용량) → 주문 의도·접수·체결·취소(증권사 대조) → 후속 가격 및 비용 → 시점 기준 연구 데이터 → 기간 분리 검증 → 모의 전진 평가.

각 단계의 원본을 변경하지 않고 입력 데이터와 전략 버전·판단 ID·주문 ID로 연결한다. 재시작 시 중복 적재를 막고, 오류나 불확실한 접수는 체결로 간주하지 않는다. 수수료·세금·체결가 누락 시 순손익은 미확인으로 남긴다. 계좌번호·API 키·토큰은 저장하지 않는다. 실계좌의 민감 데이터가 필요하다면 별도 승인된 저장 범위를 정의한다.

## 평가와 학습

기록은 학습 자체가 아니다. 시점 이후 데이터만으로 미래 수익률과 비용 차감 성과를 계산하고, 선택하지 않은 대안도 가격 이력으로 평가한다. 전략·프롬프트 변경을 버전 관리하고 과거를 재작성하지 않는다. 기간별 훈련·검증·최종 평가를 분리하고, 중첩된 관측구간은 퍼지/엠바고를 적용한다. 이후 별도의 전진 모의 평가에서 낙폭·거래비용·미체결·결측을 확인한다. 결과가 부족하면 수익성이나 실거래 준비를 주장하지 않는다.

## 현재 한계

과거 JSONL의 판단 이벤트에는 분봉 전체가 없어 과거 판단을 정확히 재현할 수 없다. 주문 접수 가격은 체결평균가가 아니며 주문 상태만으로 수수료나 순손익을 계산할 수 없다. SQLite 적재만으로 자동 학습, 예측 정확도 또는 실계좌 손실 중단이 활성화되는 것은 아니다.

별도 모의계좌의 학습 관찰기는 Jev 후보에 대해서도 5분 후 가격 방향 예측을 `jev_runs`와 `jev_predictions_latest`(매 회차 전체를 다시 계산하므로 마지막 회차만 보관한다. 회차별 사본을 쌓던 `jev_predictions`는 2026-11-18 사용자 승인으로 지웠다. 거래 원장도 같은 날부터 `events_v2` 한 표만 쓴다)에 별도 기록한다. Jev 판단 이전에 관찰 완료된 결과만 다음 예측에 사용하며, 후속 가격 시점이 Jev 판단보다 5분 이상 늦어야 표본 결과로 쓴다. 이전 이벤트에는 판단 ID가 없으므로 인접 시간과 Decision 선택을 기준으로 한 연결을 `inferred_adjacent`로 표시한다. 새 판단 ID로 연결한 경우는 `cycle_id`로 구분한다. 이 기록은 연구용이며 실제 체결·순손익이 아니고 자동 주문 필터에 사용하지 않는다. 판단값은 수익률이나 수익 보장을 뜻하지 않는다.

## 장전·장중 추가 판단의 데이터 경계

`premarket.py`는 읽기 전용 수집 결과를 `shared-etf-paper/premarket-brief.json`과 연구 이력에 남긴다. `engine_brief()`는 당일 브리프의 날짜·시간과 자료별 관찰 상태를 확인해 Jev 진입·보유와 `vibe_advisor.context()`에 `premarket_context`로 전달한다. 브리프 생성 시각을 기준으로 30분 이내 관찰된 자료를 추리고, 장전 선물·NXT 미검증 가격을 실시간 호가나 주문 지시로 쓰지 않는다. 상세 분석문은 공통 장전 분석 스킬로 별도 작성한다. 실제 판단 입력과 수집 성공은 실행 기록으로 확인한다.

vibe의 급변 관찰과 Jev 이벤트 판단은 별도 관찰·연구 기록에 남고 주문 원장을 직접 바꾸지 않는다. 16:00 이벤트 사후 재현은 관측 호가 기반의 가상 결과이므로 증권사 실제 체결이나 수익률 검증과 구분한다. 정규 엔진의 체결을 실계좌 미러가 따를 가능성 및 계좌별 주문 스위치·보호 조건은 별도로 확인한다.
