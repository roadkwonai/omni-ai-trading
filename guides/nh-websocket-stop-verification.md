# NH 실시간 손절 연결 및 검증 메모

2026-11-06 조사. 기존 실계좌 주문 경로는 변경하지 않았다. 이 문서는 구현·모의 체결 검증 또는 활성화 증거가 아니다.

## 확인한 공식 연결 조건

- 국내 시세·통보: 운영 `wss://api.nhplug.com:7070/websocket`, 모의 `wss://moapi.nhplug.com:17070/websocket`.
- `mb`는 국내 통합 호가, `d2`는 국내주식/파생 체결 통보다. 거래소 구분, 응답 필드와 모의 지원은 각 채널 명세 및 실제 구독 결과를 확인해야 한다. 통합 호가가 기존 KRX 전용 실행 조건에 적합하다고 가정하지 않는다.
- SDK 문서 기준 앱키당 동시 세션 2개, 세션당 등록 30개, 구독 전송 초당 10건. 다른 프로세스와 세션 한도를 공유하므로 프로세스 내부 세마포어만으로 전체 한도를 보장할 수 없다. REST의 TR별 초당 한도는 별도로 확인한다.
- 토큰은 기존 운영 인증 캐시를 재사용하고 로그·화면에 기록하지 않는다.

## 구현 검증 조건

1. 운영 시세와 모의 체결 통보의 환경·계좌 범위를 확인하고, 구독 응답과 실제 푸시를 구분한다. 정상 구독만으로 시세가 유효하다고 보지 않는다.
2. 연결 끊김·재접속·순서 뒤바뀜·오래된 데이터·장중단일가·VI를 처리하고 새 신호와 기존 REST 페이지 대조를 다시 확인한다. WebSocket 입력만으로 주문이나 체결을 확정하지 않는다.
3. 손절 감지 이후 기존 `nh_live_auto` 및 `nh_guarded_live` 보호 경로를 재사용한다. 지정가 취소 접수는 취소 완료가 아니며, 원주문의 취소·체결·잔량 대조가 끝나기 전 재주문하지 않는다. 부분체결, 응답 불명과 중복 통보를 테스트한다.
4. 실계좌와 분리된 모의계좌에서 실제 모의 매수 체결 → 손절 조건 → 매도 미체결 → 취소 확정 → 잔량 재주문·체결의 증권사 기록을 확인하고 지연과 호출 제한 응답을 측정한다. 동일 조건을 강제로 만들 수 없으면 해당 단계는 미검증으로 남긴다.
5. Streamlit은 연결·최근 호가 시간·통보·REST 대조·미확인 주문·실행기 보호 상태를 구분해 보여준다. 연결 불량 시 신규 진입을 막고 기존 손절 경로가 어떻게 동작하는지 명확하게 표시한다.

공식 출처: https://www.nhplug.com/openapi-docs/krstock/openapi.json 및 https://github.com/PLUG-OpenAPI/nhplug-sdk/blob/main/docs/realtime_channels.md

## 2026-11-06 장외 준비 결과

`scripts/nh_ws_monitor.py`는 KRX 호가 `ob` 또는 모의 체결 통보 `d2`를 각각 단일 구독하는 조회 전용 단기 점검기다. 통보 본문과 계좌·토큰을 출력하지 않으며, 통보는 REST 대조가 필요하다는 신호로만 해석한다. 장외 5초 접속에서 두 채널의 구독 승인 응답은 받았으나 시세·체결 데이터는 0건이었다. 구독 승인은 실제 데이터 전달의 증거가 아니다.

가짜 브로커 기반 기존 손절 주문·취소·재주문·체결 상태 전이와 WebSocket 메시지 필터 테스트는 통과했다. 실시간 트리거, 자동 재연결 및 주문 실행기 연결, Streamlit 통합, 증권사 모의 체결부터 취소·재주문까지의 장중 검증은 아직 미완료다. 이 점검기는 주문을 전송하지 않는다.

## 장외 구현: 모의 실행기 실험 옵션

`scripts/nh_paper_isolated.py --run --websocket-wakeup`은 기존 별도 모의계좌 실행기에만 실험적으로 호가 `ob` 및 모의 통보 `d2` 수신 스레드를 연결한다. `--execute` 없이는 모의 주문과 기존 미체결 주문 취소를 모두 수행하지 않는다. `--execute`를 추가해야 기존 모의 주문 경로가 활성화된다. 두 채널이 단절되면 1~30초 지수 백오프로 재접속한다. 데이터 수신은 기존 REST 전체 주문·잔고 대조를 앞당기는 신호일 뿐 체결을 확정하거나 직접 주문하지 않는다. REST 사이클은 최소 30초 간격이며 신호가 없으면 60초 후 다시 실행한다. 현재 설정과 launchd 작업에는 이 옵션을 켜지 않았다.

가짜 WebSocket·모의 브로커 및 실주문 보호 테스트에서 52개가 통과했다. 실제 장중 푸시의 최신성·재연결, 분리 모의계좌 체결·미체결 취소·재주문과 API 제한은 검증하지 않았다. 실계좌 주문 경로, 자동 재시작 설정과 Streamlit에는 연결하지 않았다.
