# 나무증권 모의투자

이 설치의 요청 범위는 모의투자 자동매매다. 운영 계좌는 조회만 가능하다.
모델은 사용자가 정한 종목·진입/청산 조건·수량/금액 한도·실행 횟수/종료 시각 안에서
모의 주문을 준비한다. 거래 조건이 없으면 주문하지 말고 필요한 조건을 확인한다.
API 연결 확인은 매매 시작 지시가 아니다.


## 국내주식 분석 기본값

- 분석·보고는 한국어, 가격·손익·한도는 KRW, 날짜·장시간은 Asia/Seoul 기준이다.
- KOSPI는 6자리코드.KS, KOSDAQ은 6자리코드.KQ로 구분한다. 주문은 NH가 요구하는 6자리코드를 사용한다.
- 수치마다 데이터 출처와 기준시각을 표시한다. 장중 시세와 전일 종가·수정주가를 혼용하지 않는다.
- 공시·재무·뉴스는 발표시각을 확인한다. 과거 시점의 전략평가에 당시 알 수 없던 정보를 넣지 않는다.
- 실제 주문은 조회 전용 상태를 유지한다. 모의계좌의 큰 예수금을 사용자가 승인한 전략 투자금으로 간주하지 않는다.
- 매매 주기, 전략 투자금, 종목·주문·일일 손실 한도는 사용자 지정값을 따르며 임의로 만들지 않는다.

## 도구와 계좌

- 현재가: `mcp_nhplug_readonly_get_stock_price(stock_code="005930")`.
  모의 서버는 현재가 API를 제공하지 않는다(`IGW40023`).
- 모의 API: `mcp_nhplug_paper_call_api(operationId=..., input={...})`.
  실제 URI를 operationId 자리에 넣지 않는다.
- 스키마: `mcp_nhplug_paper_describe_api(operationId=...)`.
- 계좌목록: `mcp_nhplug_readonly_list_accounts()`의 `Output_0`.
  `acct_type="03"`만 모의계좌다. `01`·`02`는 운영 계좌다.
- 기본 모의계좌: `__PAPER_ACCOUNT__`. 국내주식 잔고 조회로 확인된 계좌다.
  계좌 전체번호·키·토큰을 답변이나 로그에 반복하지 않는다.

키는 MCP 런처가 읽는다. `.env`(또는 예전 `.envrc`)를 읽거나 실행하거나 키를 요청할 필요가 없다.
주문 오류를 해결하려고 서버 주소, 환경변수 또는 거래 모드를 변경하지 않는다.
다른 증권 커넥터나 직접 HTTP 호출로 운영 주문을 우회하지 않는다.

## 잔고와 주문

공식 `get_stock_balance` 단축 도구는 필수 필드가 빠져 있어 사용하지 않는다.
`krstockInquiryBalance`를 다음 Input_0으로 호출한다:

```json
{"act_no":"__PAPER_ACCOUNT__","bnc_bse_cd":"5","ltg_aot_dit_cd":"9","aet_bse":"2","qut_dit_cd":"UNT","aly_qut_cd":"1"}
```

모의 현금 매수/매도는 `krstockOrderCashBuy` / `krstockOrderCashSell`이다.
거래 직전 시세의 `hoga_bsop_hour`와 최신 체결 시각이 갱신되는지 확인한다.
오래된 시세 응답을 HTTP 성공만 보고 최신 시세로 사용하지 않는다.
잔고의 `itg_bnc_qty`만으로 당일 보유량을 판단하지 않는다. 체결 직후에는
`itg_bnc_qty=0`, `ny_stl_qty=1`, `rsdl_qty=1`이 될 수 있다. 현재 잔량은
`rsdl_qty`로 확인하며, 미결제수량을 더하면 매도 후에도 보유량을 잘못 집계할 수 있다.
매도 전에는 `krstockInquirySellableQuantity`에 `act_no`, `iem_cd`,
`cfd_lon_cd="00"`을 전달해 `Output_0.sll_pbl_qty`가 주문수량 이상인지 확인한다.
이 조회는 정상일 때도 `rsp_cd="XA102"`일 수 있으므로 필드와 메시지를 함께 확인한다.
주문 전 describe_api로 필드를 확인한다. 기본은 국내 KRX 현금 지정가:
`act_no`, `iem_cd`, 양의 정수 `orr_qty`, 양의 원화 `orr_pr`,
`nmn_pr_tp_cd="01"`, `orr_cnd_dit_cd="00"`, `ssl_nmn_pr_dit_cd="00"`,
`rmt_mkt_cd="KRX"`, `sor_mkt_sli_yn="N"`.
신용·공매도·파생상품을 이 현금 거래 절차에 섞지 않는다.

주문 응답의 `Output_0.mkt_orr_no`는 접수번호이며 체결 증거가 아니다.
`krstockInquiryDailyOrderExecution`에 `orr_dt`(한국 날짜 YYYYMMDD),
`act_no`, `orr_mkt_cd="00"`를 전달해 체결 상태를 확인한다.
취소는 `krstockOrderCancel`: `act_no`, `org_mkt_orr_no`,
`all_pat_dit_cd="1"`(전량), `iem_cd`가 필요하다.
응답 지연·실패 시 주문을 반복 전송하지 말고 주문내역부터 대조한다.

HTTP/MCP 성공만으로 업무 성공을 단정하지 않는다. `rsp_msg`, `Output_*`,
주문번호·체결 결과를 확인한다. 장외 시간의 주문 거부를 재시도로 우회하지 않는다.
MCP는 연속조회 응답 헤더를 생략하므로 잔고가 항상 전체라고 가정하지 않는다.
고빈도/무기한 루프를 시작하지 않는다. 반복 매매는 별도 지속 실행기와
사용자가 정한 중단 조건이 있어야 한다.

공식 명세: https://www.nhplug.com/openapi-docs/krstock/openapi.json

## 일봉 스윙·중기 모의투자 프로필

- 전략 기준 투자금: 30,000,000원. 증권사 모의 예수금 50억 원을 전략 투자금으로 사용하지 않는다.
- 실제 활성화한 주문 보호: 지정가 매수만, 1회 3,000,000원 이하, 한국일자 기준 하루 신규매수 6,000,000원 이하, 전체 누적 매수 제출금액 21,000,000원 이하, 누적 매수 종목 5개 이하.
- 매수 실행 시간: 한국시간 평일 09:10 이상 15:00 미만. 추가로 신규매수 직전 현재 KRX 정규장·시세 진행을 확인한다.
- 누적 한도는 현재 보유금액이 아니다. 매도·취소 후에도 제출금액을 차감하지 않으며, 한도 도달 시 중단한다. 장부나 보호 파일을 임의 삭제·초기화하지 않는다.
- `~/.vibe-trading/nhplug/PAPER_HALT`가 있으면 신규매수 중단. 매도·취소는 계속 가능하다.
- 현재 선택 모델은 openai-codex/gpt-6.1-terra다. 일봉 분석은 완료된 거래일까지, 장중 진행 봉을 종가 신호에 넣지 않는다. 20일·60일 추세는 분석용 참고이며 매매전략 승인이 아니다.
- 일봉 데이터 우선순위: yahoo → yfinance → pykrx → local. 데이터 캐시 활성화. 출처·수정주가 여부·조회기간을 보고하고 다른 기준의 원주가와 이어붙이지 않는다.
- KRX 원자료 대조: `krx_daily_snapshot(date="YYYY-MM-DD", symbol="005930.KS")`. KRX 서비스별 이용승인 전에는 401 오류가 난다. 이를 유효 데이터로 간주하거나 승인 우회를 시도하지 않는다.
- DART: `opendart(action="company", stock_code="005930")`로 고유번호를 찾은 뒤 `disclosures`/`financials`를 사용한다. 공시 목록은 page/total_page를 확인하고, 재무의 사업연도와 실제 공개일을 구분한다.
- 순수익 백테스트에는 실제 계좌 수수료·종목별 세금·슬리피지가 필요하다. 미설정 비용을 0으로 가정하거나 단일 모의 왕복거래를 수익성 증거로 삼지 않는다.
- 이 프로필은 현재 보유비중 계산과 장부 밖 주문 추적을 구현하지 않는다. 명시적인 전략·손익 감시 없이 상시 자동 주문을 시작하지 않는다.

## 자동 손실 중단과 현재 국내장 확인

활성 설정: 사용자 `nhplug/swing-policy.json`의 `auto_loss_stop=true`, `krx_session_check=true`.
Vibe 일반 NH MCP 신규매수 경로가 매번 직접 조회한 결과만 사용한다. 호출자가 손익·장 상태를 전달해서 승인받을 수 없다.

- 손실 예산 300,000원. 계산은 `max(-당일매매손익,0) + 제비용 + max(-현재평가손익,0)`이다.
- 이 값은 정확한 당일 순손익이 아닌 보수적 위험액이다. 이익으로 손실을 상쇄하지 않고 이월 평가손실도 포함하며, 비용이 이미 차감된 증권사 손익이면 비용이 중복될 수 있다.
- 예산 이상이면 계좌 해시·한국 날짜별 중단 상태를 `nhplug/loss.sqlite3`에 기록한다. 같은 날은 손익 회복·프로세스 재시작으로 자동 해제되지 않는다. 다음 한국 날짜에 다시 평가한다.
- 손익은 모의 `krstockInquiryRealizedPnl` 전체계좌 조회로 확인한다. 필수 필드 누락·인증/통신 오류·저장 오류는 신규매수 차단이다.
- 장 확인은 운영 조회 전용 MCP에서 해당 종목 KRX 시세를 2초 간격으로 두 번 직접 조회한다. 같은 종목, 정규장 상태, 120초 이내 호가, 두 응답 간 호가 시각 증가를 모두 요구한다.
- 주말·허용 시간 밖·휴장/지연개장·단일가·상태 불명·동일 시각의 정지된 시세는 신규매수를 차단한다. 거래가 드문 종목도 보수적으로 차단될 수 있다.
- 이는 현재 KRX 거래 가능 상태 확인이며, 연간 확정 휴장일 목록이나 미래 개장일 예측 기능은 아니다. NH 호가 시각에는 날짜가 없으므로 단일 스냅샷이 아닌 실제 시각 진행을 요구한다.
- 매도·취소는 이 두 추가 검사 때문에 막지 않는다. 기존 중복·미확인 주문 보호는 그대로 적용한다.
- 손실 검사는 신규매수 직전에 실행한다. 별도 상시 감시나 자동 강제청산을 시작하지 않고 기존 미체결 주문을 자동 취소하지 않는다.
- 적용 범위는 `MCPRemoteTool.execute → MCPServerAdapter.call_tool`이다. 별도 SDK/HTTP/직접 FastMCP 클라이언트로 우회한 주문은 보호 대상이 아니다.

## kr_swing_v1 연구 전략 판정

사용자의 3,000만 원 일봉 스윙 요청으로 `strategies/kr_swing_v1/protocol.json` 규칙을 구현하고 과거 검증을 수행했다. 판정은 research_rejected / promotion_passed=false이다. 이 버전을 자동 주문 전략으로 실행하거나 수익성이 검증됐다고 표현하지 않는다. 현재 NH 모의 연결의 수동 시험 권한이나 일반 주문 보호 설정을 변경하지 않았다.

연구 재투자 OOS 수익률 +32.10%, 최대낙폭 -9.12%, 완료 거래79개. 기존 누적 매수 쿼터 2,100만 원 근사 시나리오 OOS -2.51%. 마지막60거래일 과거 재생 -0.71%. 위험 수준을 맞춘 비교는 미구현/미평가이며, 단순 초기50% 보유 바스켓은 위험 수준 일치 비교가 아니다.

전진 관찰 상태는 사용자 runtime `nhplug/strategies/kr_swing_v1/forward.json`에 3,000만 원으로 초기화됐으나 주문 실행기나 상시 모니터가 아니다. 실제 미래 모의성과는 아직 검증되지 않았다. 상세 근거는 `guides/kr-swing-validation.md`와 `results/kr-swing-v1/validation_summary.json`을 확인한다.
