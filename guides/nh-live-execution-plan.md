# Kodex 인버스 1주 자동매매 구현 계획

## 목표와 범위

114800 현금 지정가만 허용한다. 전체 계좌 100만 원, 1회 주문 1주·1만원 이하, 하루 신규 진입 1회를 첫 운용 상한으로 둔다. 사용자가 보유량 1주 제한을 해제했으므로 보유 수량 자체는 제한하지 않고 금액 한도로 관리한다. 외부 수동 보유는 증권사 완결 잔고·매도가능 수량과 대조해 명시적으로 편입한 경우에만 관리한다. 수동 주문과 프로세스 밖 주문은 공유 원장의 보호 대상이라고 가정하지 않는다.

## 실행 흐름

고정된 증권사 호스트·인증 파일 → 계좌 유형 확인 → 전체 주문·잔고 페이지 수집 → 현재 손익·진행하는 시세 확인 → 정책 판정 → 계좌 잠금·SQLite 영속 의도 예약 → HALT 재확인 → 재시도 없는 주문 POST → 접수 확인 → 별도 체결·취소·잔고 대조. 접수번호 누락·통신 오류·불명확 응답은 재전송하지 않고 다음 쓰기를 막는다.

키는 저장소 `.env`(`scripts/local_env.py`)의 필요한 항목만 파싱하고 출력하지 않는다. 기존 일반 NH MCP는 운영 조회 전용으로 유지하며 보호 없는 실주문 프로필을 추가하지 않는다. 실주문 실행기는 자신의 허용된 종목·계좌·수량·작업만 처리하고 원시 주문 API를 모델 도구로 노출하지 않는다.

## 실험 전략

`scripts/nh_live_strategy.py`는 주문 의도만 계산한다. 사용자는 계좌 하루 손실 2만원과 보유분 매수평균가 대비 -2% 손절을 모두 적용하도록 확정했다. 둘 중 하나라도 도달하면 청산을 판단한다. 별도로 +2% 익절은 연구 조건으로 둔다. 미체결이 있으면 새 매수 전에 대조·정리한다. 신규 진입은 완료 분봉 10개와 최근 3봉 상승·단기평균 우위를 요구하고 스프레드 0.2% 초과면 대기한다. 신호는 검증된 수익성이나 좋은 가격의 증거가 아니다.

## 완료 조건

- 위조·오래된 시세·불완전 페이지·타계좌·타종목·수량 초과·미체결·HALT가 전송 전 차단된다.
- 통신 단절·중복 요청·프로세스 재시작 후 미확인 주문이 재전송되지 않는다.
- 기존 수동 보유의 편입·매도와 취소 후 원주문 잔량이 대조된다.
- 가짜 서버 테스트 후 증권사 모의계좌에서 같은 실행 흐름을 검증한다.
- 실서버 운영 전송이 검증됐다는 증거가 없으면 운용 가능으로 설명하지 않는다.

전역 HALT와 다른 증권 연결은 임의 해제하지 않는다. 급변·미체결 때문에 손실 한도 초과 가능성이 있으며 중단 조건은 최대 손실 보증이 아니다. 현재 2% 계좌 손실 계산은 실현손실·비용·평가손실의 보수적 합으로 정확한 당일 순자산 변화와 다를 수 있다.

## 2026-11-06 활성화 검증

사용자의 NH 실계좌 활성화 요청에 따라 다른 19개 지원 브로커의 중단을 개별 HALT로 보존한 뒤 NH 전용 실행기를 `--execute --manage-existing`로 시작했다. 변경 감사는 runtime `live/nh-activation.json`에 남긴다. 실제 NH 서버에서 기존 미체결 매수 2건을 한 건씩 취소하고 원주문 잔량 0, 로컬 의도 terminal을 확인했다. 당시 보유 인버스 1주, 미체결 0건, 로컬 미확인 0건이다. 실제 매수·매도 성과와 전략 수익성 검증은 별도다.

미체결 매도는 60초 후 취소를 시도하고, 원주문 전량 취소·잔량 0이 증명된 경우에만 `replacement_of`로 새 의도를 만든다. 손절·청산 의도는 잔고가 0으로 확인될 때까지 SQLite에 유지한다. 14:45 이후 신규 진입을 막고 14:50부터 청산을 시도한다. 15:10부터는 신규 주문 없이 상태 대조만 수행하며 15:30에 종료한다. 통신 오류/미체결로 잔고가 남을 수 있으며 보장된 손실 상한이 아니다.
